## 一、DOM 事件流三阶段模型

W3C DOM Level 2 Events 规范将一次完整的事件传播分为三个连续的阶段：

```jsx
window
  └── document
       └── <html>
            └── <body>
                 └── <div id="parent">
                      └── <button id="child">点击我</button>

// 用户点击 button#child 后，事件沿此路径传播：
//
//  ① 捕获阶段（Capture Phase）
//     window → document → html → body → div#parent
//     ↓ 从根节点向下，逐级经过祖先元素
//
//  ② 目标阶段（Target Phase）
//     → button#child  ← 到达事件目标
//
//  ③ 冒泡阶段（Bubble Phase）
//     div#parent → body → html → document → window
//     ↑ 从目标向上，逐级回溯祖先元素
```

关键结论：任何一个事件处理器，都可以选择在「捕获阶段」或「冒泡阶段」触发，这是在 addEventListener 第三个参数中决定的。

## 二、事件冒泡（Event Bubbling）

### 2.1 定义

事件冒泡是 DOM 事件的默认传播方式：事件从最内层目标元素开始触发，然后逐级向上传播到外层祖先元素，直到 document 或 window。

### 2.2 基本示例

```jsx
<!-- HTML 结构 -->
<div id="outer" style="padding:40px;background:#f0f0f0;">
  外层 div
  <div id="middle" style="padding:30px;background:#ddd;">
    中层 div
    <button id="inner">点击按钮</button>
  </div>
</div>

<script>
const outer  = document.getElementById('outer')
const middle = document.getElementById('middle')
const inner  = document.getElementById('inner')

outer.addEventListener('click', () => {
  console.log('🟡 outer 被触发')
})

middle.addEventListener('click', () => {
  console.log('🟠 middle 被触发')
})

inner.addEventListener('click', () => {
  console.log('🔵 inner 被触发')
})

// 点击 button#inner 后，控制台输出顺序：
// 🔵 inner 被触发       ← 目标元素先触发
// 🟠 middle 被触发      ← 向上冒泡到 middle
// 🟡 outer 被触发       ← 继续冒泡到 outer
</script>
```

### 2.3 哪些事件会冒泡？

- ✅ 会冒泡：click, dblclick, mousedown, mouseup, keydown, keyup, focusin, focusout, touchstart, touchend, submit, change 等绝大多数事件
- ❌ 不冒泡：focus, blur, load, unload, resize, scroll（元素自身 scroll 不冒泡）, mouseenter, mouseleave, DOMContentLoaded

```jsx
// 验证事件是否冒泡：检查 bubbles 属性
document.addEventListener('click', (e) => {
  console.log('click 冒泡:', e.bubbles)  // true
})

window.addEventListener('focus', (e) => {
  console.log('focus 冒泡:', e.bubbles)  // false
})
```

### 2.4 冒泡的坑：意外触发父级事件

```jsx
// ❌ 典型陷阱：子元素点击意外触发了父元素事件
<div id="modal" class="modal" onclick="closeModal()">
  <div class="modal-content">
    <p>弹窗内容</p>
    <button id="confirmBtn">确认</button>
  </div>
</div>

<script>
// 期望：点遮罩关闭弹窗，点按钮确认操作
// 实际：点按钮后冒泡到 modal → closeModal() 也被执行了！
document.getElementById('modal').addEventListener('click', closeModal)

// ✅ 解决：阻止冒泡
document.getElementById('confirmBtn').addEventListener('click', (e) => {
  e.stopPropagation()  // 阻止冒泡到 modal
  // 执行确认逻辑
})
</script>
```

## 三、事件捕获（Event Capturing）

### 3.1 定义

事件捕获和冒泡方向相反：事件从最外层祖先（window）开始，逐级向下经过每一层 DOM 节点，最终到达目标元素。默认不会触发——必须显式指定。

### 3.2 基本示例

```jsx
<!-- 同样的 HTML 结构，全部使用捕获阶段 -->
<div id="outer" style="padding:40px;background:#f0f0f0;">
  <div id="middle" style="padding:30px;background:#ddd;">
    <button id="inner">点击按钮</button>
  </div>
</div>

<script>
const outer  = document.getElementById('outer')
const middle = document.getElementById('middle')
const inner  = document.getElementById('inner')

// 第三个参数 true = 捕获阶段触发
outer.addEventListener('click', () => {
  console.log('🟡 outer 捕获')
}, true)

middle.addEventListener('click', () => {
  console.log('🟠 middle 捕获')
}, true)

inner.addEventListener('click', () => {
  console.log('🔵 inner 被点击（目标阶段）')
})

// 点击 button#inner 后，控制台输出顺序：
// 🟡 outer 捕获       ← 从外向内！
// 🟠 middle 捕获      ← 继续向下
// 🔵 inner 被点击     ← 到达目标
</script>
```

### 3.3 混用捕获与冒泡

同一个 DOM 树上可以同时存在捕获和冒泡监听器。完整顺序：捕获阶段（外→内）→ 目标阶段 → 冒泡阶段（内→外）。

```jsx
outer.addEventListener('click', () => {
  console.log('🟡 outer 冒泡')
})  // 默认 false，冒泡阶段

middle.addEventListener('click', () => {
  console.log('🟠 middle 捕获')
}, true)  // 捕获阶段

inner.addEventListener('click', () => {
  console.log('🔵 inner 目标')
})

// 点击 inner 后输出：
// 🟠 middle 捕获       ← 捕获阶段先执行（外→内）
// 🔵 inner 目标        ← 目标阶段
// 🟡 outer 冒泡        ← 冒泡阶段后执行（内→外）

// 注意：outer 没有注册捕获监听器，所以捕获阶段只触发了 middle
// 目标阶段 inner 按注册顺序触发
// 冒泡阶段 inner 冒泡到 outer 触发冒泡监听器
```

## 四、addEventListener 第三个参数详解

```jsx
// 完整签名
target.addEventListener(type, listener, options)
target.addEventListener(type, listener, useCapture)

// 方式一：布尔值（旧式写法）
element.addEventListener('click', handler, true)   // 捕获阶段
element.addEventListener('click', handler, false)  // 冒泡阶段（默认）

// 方式二：options 对象（推荐）
element.addEventListener('click', handler, {
  capture: true,      // 捕获阶段触发
  once: true,         // 触发一次后自动移除
  passive: true,      // 不会调用 preventDefault()，提升滚动性能
  signal: controller.signal  // AbortSignal，用于移除监听器
})
```

### 4.1 capture

```jsx
// 在捕获阶段触发监听器
element.addEventListener('click', handler, { capture: true })
```

### 4.2 once

```jsx
// 自动单次触发——无需手动 removeEventListener
element.addEventListener('click', () => {
  console.log('只触发一次！')
}, { once: true })

// 等价于：
function handler() {
  console.log('只触发一次！')
  element.removeEventListener('click', handler)
}
element.addEventListener('click', handler)
```

### 4.3 passive

```jsx
// 滚动性能优化关键：
// 浏览器在 touchstart / touchmove / wheel 中需要等 JS 执行完
// 才能判断是否要调用 preventDefault() 阻止滚动。
// passive: true 承诺不再调用 preventDefault()，浏览器可立即滚动。

// ✅ 推荐：滚动监听器加上 passive
document.addEventListener('touchmove', handleTouch, { passive: true })

// ❌ 会触发控制台警告（Chrome）：
document.addEventListener('touchmove', (e) => {
  e.preventDefault()  // Unable to preventDefault inside passive event listener
}, { passive: true })

// 移动端滚动性能与 passive 密切相关
// 2026 年的最佳实践：所有 scroll/touch 事件都加 passive
```

### 4.4 signal（AbortController）

```jsx
// 优雅地批量移除监听器
const controller = new AbortController()

element.addEventListener('click', handler, { signal: controller.signal })
element.addEventListener('keydown', handler2, { signal: controller.signal })

// 一次性移除所有关联的监听器
controller.abort()

// React/Vue 中也可以用——组件卸载时 clean：
useEffect(() => {
  const controller = new AbortController()
  window.addEventListener('resize', handleResize, { signal: controller.signal })
  return () => controller.abort()
}, [])
```

## 五、stopPropagation 与 stopImmediatePropagation

### 5.1 stopPropagation()

阻止事件继续向下（捕获）或向上（冒泡）传播。但当前元素上绑定的其他同事件监听器仍会执行。

```jsx
// 阻止冒泡
inner.addEventListener('click', (e) => {
  e.stopPropagation()  // 阻止事件冒泡到 middle/outer
  console.log('inner 被点击')
})

// 阻止捕获
outer.addEventListener('click', (e) => {
  e.stopPropagation()  // 阻止事件继续向下捕获
  console.log('outer 捕获')
}, true)

// 注意：stopPropagation 不阻止当前元素上的其他监听器！
inner.addEventListener('click', () => console.log('监听器1'))
inner.addEventListener('click', (e) => {
  e.stopPropagation()
  console.log('监听器2，调用了 stopPropagation')
})
inner.addEventListener('click', () => console.log('监听器3 仍会执行！'))
// 输出：监听器1 → 监听器2 → 监听器3（全部执行！）
```

### 5.2 stopImmediatePropagation()

更强力的版本：不仅阻止传播，还会阻止当前元素上剩余的同类事件监听器。

```jsx
inner.addEventListener('click', () => console.log('监听器1'))
inner.addEventListener('click', (e) => {
  e.stopImmediatePropagation()
  console.log('监听器2，调用了 stopImmediatePropagation')
})
inner.addEventListener('click', () => console.log('监听器3 不会执行！'))

// 输出：监听器1 → 监听器2（到此为止）
```

### 5.3 preventDefault()

与上面两个无直接关系——它阻止浏览器的默认行为，但不会阻止事件传播。

```jsx
// 阻止链接跳转，但事件仍会冒泡
document.querySelector('a').addEventListener('click', (e) => {
  e.preventDefault()  // 不跳转
  // 但事件仍会冒泡到父级！
})

// 阻止表单提交
document.querySelector('form').addEventListener('submit', (e) => {
  e.preventDefault()
  // AJAX 提交逻辑
})

// 三者对比：
// stopPropagation()         阻止传播（冒泡/捕获）
// stopImmediatePropagation() 阻止传播 + 阻止同级其他监听器
// preventDefault()           阻止浏览器默认行为（不阻止传播）
```

## 六、事件委托（Event Delegation）

事件委托是事件冒泡最重要的实战应用。核心思想：不直接在每个子元素上绑定事件，而是在共同祖先上监听，利用冒泡机制统一处理。

### 6.1 为什么需要事件委托

- 动态元素：后续通过 JS 添加的新元素，无法被已绑定的直接监听器捕获
- 性能：1000 个 li 绑定 1000 个事件 vs 只在父 ul 上绑定 1 个
- 代码简洁：统一管理，避免重复绑定/解绑逻辑

### 6.2 经典案例：动态列表

```jsx
<!-- 动态待办列表 -->
<ul id="todoList">
  <li><span>买牛奶</span> <button class="delete">删除</button></li>
  <li><span>写报告</span> <button class="delete">删除</button></li>
</ul>
<button id="addBtn">添加</button>

<script>
const list = document.getElementById('todoList')

// ❌ 错误做法：直接在 button 上绑定
document.querySelectorAll('.delete').forEach(btn => {
  btn.addEventListener('click', (e) => {
    e.target.closest('li').remove()
  })
})
// 问题：后续添加的 button.delete 没有事件监听器！

// ✅ 事件委托：在 ul 上统一监听
list.addEventListener('click', (e) => {
  if (e.target.classList.contains('delete')) {
    e.target.closest('li').remove()
  }
})

// ✅ 也可以委托切换完成状态
list.addEventListener('click', (e) => {
  if (e.target.tagName === 'SPAN') {
    e.target.classList.toggle('completed')
  }
})

// 新添加的元素自动支持删除、切换
document.getElementById('addBtn').addEventListener('click', () => {
  const li = document.createElement('li')
  li.innerHTML = '<span>新任务</span> <button class="delete">删除</button>'
  list.appendChild(li)
  // ✅ 不需要给新 button 绑事件！
})
</script>
```

### 6.3 事件委托的匹配策略

```jsx
// 策略1: tagName 匹配（简单场景）
container.addEventListener('click', (e) => {
  if (e.target.tagName === 'BUTTON') { /* ... */ }
})

// 策略2: classList 匹配（推荐）
container.addEventListener('click', (e) => {
  if (e.target.classList.contains('my-action')) { /* ... */ }
})

// 策略3: data-attribute 匹配（语义化）
container.addEventListener('click', (e) => {
  const action = e.target.dataset.action
  switch (action) {
    case 'edit':   handleEdit(e.target); break
    case 'delete': handleDelete(e.target); break
    case 'share':  handleShare(e.target); break
  }
})
// HTML: <button data-action="edit">编辑</button>

// 策略4: matches() + closest() 组合（嵌套图标场景）
container.addEventListener('click', (e) => {
  const btn = e.target.closest('.action-btn')
  if (!btn) return  // 不关心的事件，跳过
  const action = btn.dataset.action
  // 处理逻辑...
})
```

### 6.4 事件委托的局限

- 不冒泡的事件（focus/blur/mouseenter 等）无法使用委托——需要用 focusin/focusout 或 mouseover/mouseout 替代
- 某些事件在到达父级前可能被 stopPropagation() 阻断
- 深层嵌套场景下需要通过 closest() 或循环向上查找来确定真正的目标元素

## 七、event.target vs event.currentTarget

这是面试高频问题。二者的区别在事件委托中尤其关键：

```jsx
<div id="parent">
  <button id="child"><span>点我</span></button>
</div>

<script>
const parent = document.getElementById('parent')

parent.addEventListener('click', function(e) {
  console.log('event.target:',        e.target)
  // → 实际被点击的元素（最深层那个）
  // 如果点击 span：输出 <span>点我</span>
  // 如果点击 button：输出 <button id="child"> ...

  console.log('event.currentTarget:', e.currentTarget)
  // → 绑定监听器的那个元素（始终不变）
  // 始终输出：<div id="parent"> ...

  // === this 指向 ===
  console.log('this:',                this)
  // → 和 currentTarget 相同（在普通函数中）
  // 箭头函数中 this 不等于 currentTarget！
})

// 总结：
// target        — 事件起源（最深层的触发元素）
// currentTarget — 当前处理事件的元素（绑监听器的那个）
// this          — 函数内的 this，指向 currentTarget（仅普通函数）
</script>
```

## 八、完整事件流实战演示

下面是一个完整的 Demo，展示捕获→目标→冒泡全流程，并对比 target 与 currentTarget：

```jsx
<!-- 完整 Demo -->
<style>
  * { box-sizing: border-box; margin: 0; padding: 0; }
  .demo { padding: 20px; border: 2px solid #333; margin: 10px; min-height: 60px; }
  #grand  { background: #ffcccc; }
  #parent { background: #ccffcc; }
  #child  { background: #ccccff; }
</style>

<div id="grand" class="demo">
  <p>爷爷 (grand)</p>
  <div id="parent" class="demo">
    <p>爸爸 (parent)</p>
    <button id="child" class="demo">儿子 (child)</button>
  </div>
</div>

<script>
function handler(phase, name) {
  return function(e) {
    console.log(`[${phase}] ${name} — target: ${e.target.id}, currentTarget: ${e.currentTarget.id}`)
  }
}

// 捕获阶段（外→内）
document.getElementById('grand') .addEventListener('click', handler('捕获', 'grand'),  true)
document.getElementById('parent').addEventListener('click', handler('捕获', 'parent'), true)
document.getElementById('child') .addEventListener('click', handler('捕获', 'child'),  true)

// 冒泡阶段（内→外）
document.getElementById('child') .addEventListener('click', handler('冒泡', 'child'))
document.getElementById('parent').addEventListener('click', handler('冒泡', 'parent'))
document.getElementById('grand') .addEventListener('click', handler('冒泡', 'grand'))

// 点击 button#child 后控制台输出：
// [捕获] grand  — target: child, currentTarget: grand
// [捕获] parent — target: child, currentTarget: parent
// [捕获] child  — target: child, currentTarget: child   ← 到达目标
// [冒泡] child  — target: child, currentTarget: child
// [冒泡] parent — target: child, currentTarget: parent
// [冒泡] grand  — target: child, currentTarget: grand

// 注意：目标阶段按注册顺序触发（先捕获后冒泡）
// child 的两个监听器按代码顺序执行：捕获先于冒泡
</script>
```

从输出可验证：target 始终是触发元素 child，currentTarget 依次是捕获/冒泡路径上处理事件的那个祖先。

## 九、常见场景与易错陷阱

### 9.1 移动端 click 延迟问题

```jsx
// 历史问题（现在移动端已大幅改善，但理解原理仍重要）
// 移动端浏览器在 touchend 后会等待 300ms
// 判断用户是否要双击缩放，然后才触发 click

// 解决（传统方式）
element.addEventListener('touchend', (e) => {
  e.preventDefault()  // 立即触发，不等待 click
  // 处理逻辑...
})

// 2026 现代方案：直接在 HTML head 中声明
// <meta name="viewport" content="width=device-width, user-scalable=no">
// 或使用 pointer 事件替代 touch + click 组合
```

### 9.2 focus/blur 不冒泡 → 用 focusin/focusout

```jsx
// ❌ 不冒泡——无法委托
// parent.addEventListener('focus', handler)  // 捕获不到子元素的 focus

// ✅ 使用 focusin / focusout（会冒泡）
parent.addEventListener('focusin', (e) => {
  console.log('子元素获得了焦点:', e.target)
})

// 表单校验委托示例
document.getElementById('form').addEventListener('focusout', (e) => {
  if (e.target.tagName === 'INPUT') {
    validateField(e.target)
  }
})

// focusin / focusout 对比 focus / blur：
//   focus/blur        不冒泡，可捕获
//   focusin/focusout  会冒泡，不可在捕获阶段使用
```

### 9.3 mouseenter / mouseleave 不冒泡

```jsx
// mouseenter 和 mouseleave 不冒泡——这是合理的
// 否则鼠标从一个嵌套子元素移到另一个子元素时
// 父级会不停地触发 enter/leave

// 如果需要在父子间感知鼠标进出，用 mouseover/mouseout（会冒泡）
parent.addEventListener('mouseover', (e) => {
  // mouseover 会在每次进入子元素时触发（冒泡）
  console.log('鼠标进入了:', e.target)
})

// 或者用 relatedTarget 判断真正的进出
parent.addEventListener('mouseover', (e) => {
  if (!parent.contains(e.relatedTarget)) {
    console.log('鼠标真正进入了 parent')
  }
})
```

### 9.4 动态绑定与事件覆盖

```jsx
// ❌ 常见错误：多次调用导致重复绑定
let count = 0
document.getElementById('btn').addEventListener('click', () => {
  count++
  console.log('点击次数:', count)
})
// 如果这段代码被多次执行（React 重渲染、路由切换等）
// 每次都会新增一个监听器，count 增加次数翻倍！

// ✅ 解决
// 方案1：使用 { once: true }（一次性事件）
// 方案2：先移除再添加
const btn = document.getElementById('btn')
function handler() { /* ... */ }
btn.removeEventListener('click', handler)  // 先移除
btn.addEventListener('click', handler)     // 再添加
// 注意：必须用同一函数引用！匿名函数无法被 removeEventListener 移除

// 方案3：AbortController（最优雅）
let controller = new AbortController()
btn.addEventListener('click', handler, { signal: controller.signal })
// 重新绑定时：
controller.abort()  // 移除旧监听器
controller = new AbortController()
btn.addEventListener('click', handler, { signal: controller.signal })
```

### 9.5 异步场景下的事件

```jsx
// async 事件处理器中的 e.preventDefault 在同步调用时仍然有效
document.querySelector('a').addEventListener('click', async (e) => {
  e.preventDefault()  // 同步调用，不影响效果
  await fetch('/api/track')
})

// ✅ 真正需要注意的是：异步前保存所需的事件数据
document.querySelector('form').addEventListener('submit', (e) => {
  e.preventDefault()
  const formData = new FormData(e.target)
  const target = e.target  // 保存引用
  fetch('/api/submit', { method: 'POST', body: formData })
    .then(() => target.reset())
})
```

### 9.6 嵌套弹窗/模态框的关闭逻辑

```jsx
// ❌ 经典 bug：点弹窗内部就关了
modal.addEventListener('click', () => closeModal())

// ✅ 判断点击的是遮罩还是内容
modal.addEventListener('click', (e) => {
  if (e.target === e.currentTarget) {
    closeModal()
  }
})

// 更健壮：判断点击是否在 content 之外
const content = modal.querySelector('.modal-content')
modal.addEventListener('click', (e) => {
  if (!content.contains(e.target)) {
    closeModal()
  }
})
```

## 十、与现代前端框架的关系

### 10.1 React

```jsx
// React 17+ 的合成事件都绑定在 root 节点上（事件委托）
// React 内部实现了自己的合成事件层（SyntheticEvent）
// 所以 e.nativeEvent.stopImmediatePropagation() 可能不符合预期

function App() {
  return (
    <div onClick={() => console.log('冒泡')}>
      <button onClick={(e) => {
        e.stopPropagation()      // ✅ 阻止 React 合成事件冒泡
        e.nativeEvent.stopImmediatePropagation()  // 阻止原生事件
      }}>
        点击
      </button>
    </div>
  )
}

// React 合成事件注意事项：
// 1. 合成事件会在事件委托层统一处理
// 2. 所有事件默认在冒泡阶段触发（React 不使用捕获阶段）
// 3. onClickCapture 可以用捕获阶段:
//    <div onClickCapture={() => console.log('捕获')}>
// 4. 事件回调中的 e 是 SyntheticEvent，会被池化复用
// 5. async 访问事件属性不需要 e.persist()（React 17+）
```

### 10.2 Vue

```jsx
<!-- Vue 模板中事件默认为冒泡阶段 -->
<div @click="handleParent">
  <button @click="handleChild">点击</button>
</div>

<!-- 捕获阶段用 .capture 修饰符 -->
<div @click.capture="handleCapture">
  <button>点击</button>
</div>

<!-- 阻止冒泡用 .stop 修饰符 -->
<button @click.stop="handleClick">不冒泡</button>

<!-- 阻止默认行为用 .prevent -->
<form @submit.prevent="handleSubmit">

<!-- 组合使用 -->
<button @click.stop.prevent="handleClick">
  既阻止冒泡又阻止默认
</button>

<!-- 常用修饰符汇总 -->
@click.stop     → e.stopPropagation()
@click.prevent  → e.preventDefault()
@click.self     → 只有 e.target === e.currentTarget 时触发
@click.once     → 只触发一次
@click.capture  → 捕获阶段触发
@click.passive  → 不会 preventDefault（用于滚动优化）
@keydown.enter  → 只有 Enter 键
@keydown.ctrl.s → Ctrl+S 组合键
```

### 10.3 原生 Web Components

```jsx
// Shadow DOM 中的事件会冒泡到 Shadow Root
// 但 event.target 会被重写为宿主元素（封装性）
class MyButton extends HTMLElement {
  constructor() {
    super()
    const shadow = this.attachShadow({ mode: 'open' })
    shadow.innerHTML = '<button><slot></slot></button>'
  }
}
customElements.define('my-button', MyButton)

// 使用：
<my-button id="btn">点击</my-button>
<script>
document.getElementById('btn').addEventListener('click', (e) => {
  console.log(e.target)  // <my-button> （被重写！）
  console.log(e.composedPath())  // 完整路径（Shadow DOM 内部可见）
})
</script>

// 注意：
// 1. composed: true 的事件会穿透 Shadow DOM 边界
// 2. e.composedPath() 返回包含 Shadow DOM 内元素的完整路径
// 3. 自定义事件需设置 { composed: true } 才能穿透
```

## 十一、event.eventPhase 阶段检测

```jsx
element.addEventListener('click', (e) => {
  switch (e.eventPhase) {
    case Event.CAPTURING_PHASE:  // 1
      console.log('捕获阶段')
      break
    case Event.AT_TARGET:        // 2
      console.log('目标阶段')
      break
    case Event.BUBBLING_PHASE:   // 3
      console.log('冒泡阶段')
      break
  }
})

// 实用场景：调试时确定事件是在哪个阶段触发的
// 这在排查复杂的事件委托问题时非常有用
```
