# 前端图片加载方案（全面详解）

## 一、图片格式选型

| 格式 | 压缩类型 | 透明支持 | 动图 | 推荐场景 | 浏览器兼容 |
| --- | --- | --- | --- | --- | --- |
| **JPEG** | 有损 | ❌ | ❌ | 照片、复杂色彩图片 | 全兼容 |
| **PNG** | 无损 | ✅ | ❌ | Logo、图标、透明背景图 | 全兼容 |
| **WebP** | 有损/无损 | ✅ | ✅ | Google 推荐，体积比 JPEG 小 25-35% | Chrome/Firefox/Edge；Safari 14+ |
| **AVIF** | 有损/无损 | ✅ | ✅ | 新一代格式，比 WebP 再小 20-30% | Chrome 85+、Firefox 93+、Safari 16+ |
| **SVG** | 矢量 | ✅ | ✅ | 图标、图表、简单插画、Logo | 全兼容 |
| **GIF** | 有损 | ✅ | ✅ | 简单动图（已被 WebP/MP4 取代） | 全兼容 |

### 格式选择决策树

1. 是矢量图（图标/Logo/简单图形）？ → **SVG**
2. 需要透明背景？ → **PNG** 或 **WebP** 或 **AVIF**
3. 需要动图？ → **WebP** 动画 或 **MP4**（远小于 GIF）
4. 照片类图片？ → **AVIF** > **WebP** > **JPEG**

### 推荐优先级

```
AVIF → WebP → JPEG/PNG（作为降级方案）
```

## 二、图片加载策略

### 2.1 懒加载（Lazy Loading）

#### 原生 HTML 方式

```html
<img src="image.jpg" loading="lazy" alt="图片描述" />
```

- `loading="lazy"`：滚动到视口附近时才开始加载
- `loading="eager"`：立即加载（默认值）
- 浏览器兼容：Chrome 77+、Firefox 75+、Edge 79+、Safari 15.4+

**优点**：零代码侵入，浏览器原生支持  

**缺点**：无法控制懒加载的触发距离，不支持自定义加载动画

#### Intersection Observer 手动实现

```jsx
const imageObserver = new IntersectionObserver((entries, observer) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      if (img.dataset.srcset) {
        img.srcset = img.dataset.srcset;
      }
      img.classList.remove('lazy');
      observer.unobserve(img);
    }
  });
}, {
  rootMargin: '200px 0px',  // 提前 200px 开始加载
  threshold: 0.01
});

document.querySelectorAll('img[data-src]').forEach(img => {
  imageObserver.observe(img);
});
```

**rootMargin 最佳实践**：

- 快速滚动的页面：`300px-500px`
- 常规页面：`200px`
- 图片密集的页面：`100px`

#### 进阶：渐进式占位技术

| 技术 | 原理 | 体积 | 效果 |
| --- | --- | --- | --- |
| **LQIP** | 加载 20-40px 宽的极度压缩图 | ~200-400 bytes | 模糊的彩色占位 |
| **SQIP** | 用 SVG 几何图形模拟图像轮廓 | ~500-800 bytes | 抽象几何轮廓 |
| **BlurHash** | 用极短字符串生成模糊渐变 | 20-30 bytes | 模糊渐变色块 |
| **Dominant Color** | 提取主色调作为背景 | ~6 bytes | 纯色背景 |

**BlurHash 示例：**

```jsx
import { decode } from 'blurhash';

const canvas = document.createElement('canvas');
const ctx = canvas.getContext('2d');
const pixels = decode('LKO2?U%2Tw=w]~RBVZRi};RPxuwH', 32, 32);
const imageData = new ImageData(pixels, 32, 32);
ctx.putImageData(imageData, 0, 0);

// 作为 CSS 背景图或 <img> placeholder
img.style.backgroundImage = `url(${canvas.toDataURL()})`;
```

### 2.2 预加载（Preload / Prefetch）

#### Resource Hints 分类

| 指令 | 优先级 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| `preload` | 高 | 当前页面**必需**的关键资源 | 首屏大图、关键字体 |
| `prefetch` | 低（空闲时） | **未来**页面可能需要的资源 | 下一页的背景图 |
| `preconnect` | 中 | 提前建立到第三方域的连接 | CDN 域名 |
| `dns-prefetch` | 最低 | 仅提前 DNS 解析 | 多个可能的 CDN 域名 |

#### 代码示例

```html
<!-- 首屏关键图片 → 高优先级预加载 -->
<link rel="preload" as="image" href="/hero-banner.jpg"
      imagesrcset="/hero-480.jpg 480w, /hero-800.jpg 800w, /hero-1200.jpg 1200w"
      imagesizes="100vw" />

<!-- 下一页可能需要的大图 → 空闲时预加载 -->
<link rel="prefetch" as="image" href="/next-page-bg.jpg" />

<!-- 提前建立 CDN 连接（DNS + TCP + TLS） -->
<link rel="preconnect" href="https://cdn.example.com" />

<!-- 仅 DNS 预解析（当有多个可能域名时） -->
<link rel="dns-prefetch" href="https://img-cdn.example.com" />
```

#### Preload 使用注意事项

1. 只对关键资源使用 `preload`，滥用会抢占带宽，反而降低性能
2. 必须搭配 `as` 属性，否则浏览器无法正确设定优先级
3. 如果 3 秒内未使用，Chrome 会在 Console 打印警告
4. 配合 `imagesrcset` 和 `imagesizes` 可以预加载响应式图片

#### 动态 Preload（JS）

```jsx
function preloadImage(url) {
  const link = document.createElement('link');
  link.rel = 'preload';
  link.as = 'image';
  link.href = url;
  document.head.appendChild(link);
}

// 鼠标悬停时预加载
button.addEventListener('mouseenter', () => {
  preloadImage('/hover-state-image.jpg');
});
```

### 2.3 响应式图片（Responsive Images）

#### srcset + sizes（按视口宽度选择资源）

```html
<img
  src="default-800.jpg"
  srcset="
    small-480.jpg   480w,
    medium-800.jpg  800w,
    large-1200.jpg 1200w,
    xlarge-1600.jpg 1600w
  "
  sizes="
    (max-width: 600px) 100vw,
    (max-width: 1200px) 50vw,
    33vw
  "
  alt="响应式图片"
/>
```

**sizes 解析逻辑**：

- 视口 ≤ 600px：图片占 100vw → 选 ≥ 600px 最近的图 → `small-480.jpg`? 不，选 800w
- 600px < 视口 ≤ 1200px：占 50vw → 选 ≥ 600px 最近的图 → `medium-800.jpg`
- 视口 > 1200px：占 33vw → 如果 33% * 1920 = 633px → 选 `medium-800.jpg`

#### picture 元素（按格式/媒体条件选择）

```html
<picture>
  <!-- AVIF 支持 → 最优先 -->
  <source srcset="image.avif" type="image/avif" />

  <!-- WebP 支持 → 次优先 -->
  <source srcset="image.webp" type="image/webp" />

  <!-- 小屏设备使用裁剪版本 -->
  <source srcset="image-mobile.jpg" media="(max-width: 600px)" />

  <!-- 降级方案（兜底） -->
  <img src="image.jpg" alt="图片" loading="lazy" />
</picture>
```

#### 按像素密度（DPR）

```html
<img
  src="photo-1x.jpg"
  srcset="photo-1x.jpg 1x, photo-2x.jpg 2x, photo-3x.jpg 3x"
  alt="高清图"
/>
```

- 普通屏（1x DPR）→ `photo-1x.jpg`
- Retina 屏（2x DPR）→ `photo-2x.jpg`
- 超高清屏（3x DPR）→ `photo-3x.jpg`

### 2.4 渐进式加载

#### 渐进式 JPEG（Progressive JPEG）

编码时选择 Progressive 模式，浏览器先展示低质量全图，逐步变清晰。

| 特性 | 基线 JPEG | 渐进式 JPEG |
| --- | --- | --- |
| 加载体验 | 从上到下逐行刷出 | 模糊全图 → 逐渐清晰 |
| 文件大小 | 略小（约 2-5%） | 略大 |
| 用户感知 | 较慢 | 较快（立即看到内容） |

#### 三阶段渐进加载

```jsx
class ProgressiveImage {
  constructor(imgElement, sources) {
    this.img = imgElement;
    this.sources = sources; // { blurHash, thumbnail, full }
  }

  async load() {
    // 阶段 1：立即显示 blurHash / 极小占位图
    this.img.style.backgroundImage = this.sources.blurHash;

    // 阶段 2：加载缩略图（如 200px 宽）
    await this.loadImage(this.sources.thumbnail);
    this.img.src = this.sources.thumbnail;
    this.img.classList.add('loaded-thumb');

    // 阶段 3：加载原图
    await this.loadImage(this.sources.full);
    this.img.src = this.sources.full;
    this.img.style.backgroundImage = 'none';
    this.img.classList.add('loaded-full');
  }

  loadImage(src) {
    return new Promise((resolve, reject) => {
      const tempImg = new Image();
      tempImg.onload = resolve;
      tempImg.onerror = reject;
      tempImg.src = src;
    });
  }
}

// 使用
new ProgressiveImage(document.querySelector('.hero-img'), {
  blurHash: decodeBlurHash('LKO2?U%2Tw=w]~RBVZRi};RPxuwH'),
  thumbnail: '/hero-thumb-200.jpg',
  full: '/hero-full-1200.jpg',
}).load();
```

## 三、CDN 图片处理

### 3.1 动态处理参数

通过 CDN URL 参数实现按需处理，源站只存原始高清图：

```
https://cdn.example.com/image.jpg?width=400&height=300&format=webp&quality=80&fit=cover
```

### 常用参数

| 参数 | 说明 | 示例 |
| --- | --- | --- |
| `width` / `height` | 目标尺寸 | `width=400` |
| `format` | 输出格式 | `format=webp` / `format=avif` |
| `quality` | 质量 1-100 | `quality=80` |
| `fit` | 缩放模式 | `cover` / `contain` / `fill` / `inside` / `outside` |
| `crop` | 裁剪区域 | `crop=faces` / `crop=entropy` |
| `blur` | 模糊度 | `blur=20`（用于占位图） |
| `sharpen` | 锐化 | `sharpen=5` |

### 3.2 内容协商（Content Negotiation）

**Accept 请求头自动判断格式：**

```
# 源站 Nginx 配合 CDN
location /images/ {
    # 根据 Accept 头判断客户端支持的格式
    if ($http_accept ~* "image/avif") {
        add_header Vary Accept;
    }
}
```

## 四、加载状态与容错处理

### 4.1 加载状态管理

```jsx
class ImageLoader {
  static STATE = {
    IDLE: 'idle',
    LOADING: 'loading',
    LOADED: 'loaded',
    ERROR: 'error'
  };

  constructor(imgElement) {
    this.img = imgElement;
    this.state = ImageLoader.STATE.IDLE;
    this.retryCount = 0;
    this.maxRetries = 3;
  }

  async load(src, fallbackSrc = null) {
    this.state = ImageLoader.STATE.LOADING;
    this.img.dataset.state = 'loading';

    try {
      await this.loadImage(src);
      this.img.src = src;
      this.state = ImageLoader.STATE.LOADED;
      this.img.dataset.state = 'loaded';
    } catch (error) {
      if (this.retryCount < this.maxRetries) {
        this.retryCount++;
        console.warn(`Retry ${this.retryCount}/${this.maxRetries}: ${src}`);
        await this.delay(1000 * this.retryCount); // 指数退避
        return this.load(src, fallbackSrc);
      }

      this.state = ImageLoader.STATE.ERROR;
      this.img.dataset.state = 'error';

      if (fallbackSrc) {
        console.warn(`Falling back to: ${fallbackSrc}`);
        return this.load(fallbackSrc, null); // 降级图不再重试
      }
    }
  }

  loadImage(src) {
    return new Promise((resolve, reject) => {
      const tempImg = new Image();
      tempImg.onload = () => resolve(tempImg);
      tempImg.onerror = () => reject(new Error(`Failed to load: ${src}`));
      tempImg.src = src;
    });
  }

  delay(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}
```

### 4.2 加载失败降级策略

**HTML 内联降级：**

```html
<!-- 基础降级（注意避免死循环） -->
<img src="original.jpg"
     onerror="if(this.src!=='/fallback.png')this.src='/fallback.png'"
     alt="图片" />
```

**多级降级策略：**

```jsx
const FALLBACK_CHAIN = [
  '/images/full-quality.jpg',      // 原图
  '/images/compressed.jpg',        // 压缩版（不同 CDN）
  '/images/low-quality.jpg',       // 低质量版（同 CDN 另一个路径）
  '/images/fallback-placeholder.svg' // 最终降级占位图
];

async function loadWithFallback(img, chain) {
  for (const src of chain) {
    try {
      await loadImage(img, src);
      return; // 成功则退出
    } catch (e) {
      console.warn(`Failed: ${src}, trying next fallback...`);
    }
  }
  // 全部失败 → 隐藏图片或显示纯色占位
  img.style.display = 'none';
}
```

```css
/* 加载中：骨架屏效果 */

img:not([data-state="loaded"]) {
  opacity: 0;
}
```

## 五、性能优化技巧

### 5.1 图片压缩

| 工具 | 类型 | 适用场景 | 特点 |
| --- | --- | --- | --- |
| **Sharp** | Node.js 库 | 构建时/服务端批量处理 | 速度极快，API 简洁 |
| **imagemin** | Node.js 库 | 构建时压缩 | 插件生态丰富 |
| **Squoosh** | Web App / CLI | 手动精细调整 | Google 出品，支持 AVIF |
| **TinyPNG** | API / Web | 开发者常用 | 智能有损压缩，效果好 |
| **pngquant** | CLI | PNG 有损压缩 | 命令行批量处理 |

#### Sharp 构建时压缩示例

```jsx
// webpack / vite 构建配置中的图片处理
const sharp = require('sharp');

async function optimizeImage(input, output) {
  await sharp(input)
    .resize(1200, 800, { fit: 'inside', withoutEnlargement: true })
    .webp({ quality: 80 })
    .toFile(output.replace(/\.(jpg|png)$/, '.webp'));
}

// 质量建议：JPEG 70-80、WebP 75-85、AVIF 50-70
```

### 5.2 缓存策略

```
# 文件名带 hash → 永久缓存
Cache-Control: public, max-age=31536000, immutable

# 示例文件名
banner.a3f2b8c9.jpg    → 可以安全永久缓存
banner.jpg?version=2   → 不推荐（有些 CDN 忽略 query 参数）
```

**immutable 指令说明**：

- 告知浏览器：该资源内容**永远不变**
- 浏览器不会发送 304 条件请求验证
- 必须搭配 hash 文件名使用，否则资源更新后用户看不到

### 5.3 请求优化

| 策略 | 说明 | 适用 |
| --- | --- | --- |
| **SVG Sprite** | 多个小图标合并为一个 SVG | 图标系统 |
| **HTTP/2 多路复用** | 无需 Domain Sharding | 所有场景 |
| **`decoding="async"`** | 图片解码不阻塞主线程 | 非首屏图片 |
| **`fetchpriority="high"`** | 提升关键图片的加载优先级 | 首屏大图 |

```html
<!-- 首屏大图：最高优先级 -->
<img src="hero.jpg" fetchpriority="high" decoding="sync" />

<!-- 非首屏图片：异步解码 -->
<img src="below-fold.jpg" fetchpriority="low" decoding="async" />
```

### 5.4 防止布局偏移（CLS 优化）

```html
<style>
  .image-wrapper {
    position: relative;
    width: 100%;
    /* 通过 aspect-ratio 或 padding-bottom 预留空间 */
    aspect-ratio: 16 / 9;
    overflow: hidden;
    background: #f0f0f0;
  }
  .image-wrapper img {
    position: absolute;
    top: 0;
    left: 0;
    width: 100%;
    height: 100%;
    object-fit: cover;
  }
</style>

<div class="image-wrapper">
  <img src="banner.jpg" alt="Banner" loading="lazy" />
</div>
```

**固定宽高比方法对比**：

| 方法 | 兼容性 | 推荐 |
| --- | --- | --- |
| `aspect-ratio: 16/9` | Chrome 88+ / Firefox 89+ / Safari 15+ | ✅ 首选 |
| `padding-bottom: 56.25%` | 全兼容 | 兜底方案 |
| 固定 width + height 属性 | 全兼容 | ✅ 简单场景 |

```tsx
import Image from 'next/image';

// 本地图片：自动宽高、blurDataURL
import heroImg from '@/public/hero.jpg';

export default function Page() {

    </>
  );
}
```

**next.config.js 远程图片配置：**

```jsx
module.exports = {
  images: {
    formats: ['image/avif', 'image/webp'],
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'cdn.example.com',

    deviceSizes: [480, 768, 1024, 1280, 1536],

};
```

### 7.1 虚拟列表中的图片

```jsx
// 在虚拟列表中，图片也需要虚拟化
// 使用 react-window + 动态懒加载
import { FixedSizeList } from 'react-window';

function Row({ index, style, data }) {
  const item = data[index];
  return (
    <div style={style}>
      <img
        data-src={item.thumbnailUrl}    // 先不设置 src
        src="data:image/gif;base64,..."  // 1×1 透明占位
        loading="lazy"
        alt={item.title}
        ref={node => node && (node.src = node.dataset.src)}
      />
    </div>
  );
}
```

### 7.2 Canvas 中加载图片

```jsx
// 在处理图片后释放内存
async function processImageInCanvas(url) {
  const img = await loadImage(url);
  const canvas = document.createElement('canvas');
  const ctx = canvas.getContext('2d');

  canvas.width = img.width;
  canvas.height = img.height;
  ctx.drawImage(img, 0, 0);

  // 处理完成后释放图片内存
  img.src = '';
  URL.revokeObjectURL(img.src);

  return canvas;
}
```

### 7.3 Service Worker 缓存策略

```jsx
// sw.js — 图片缓存优先策略
self.addEventListener('fetch', (event) => {
  if (event.request.destination === 'image') {
    event.respondWith(
      caches.match(event.request).then((cached) => {
        // 缓存命中 → 直接返回
        if (cached) return cached;

        // 网络请求 → 缓存后返回
        return fetch(event.request).then((response) => {
          const clone = response.clone();
          caches.open('image-cache-v1').then((cache) => {
            cache.put(event.request, clone);
          });
          return response;
        });
      })
    );
  }
});
```

## 八、性能监控指标

### 关键指标

| 指标 | 说明 | 优化目标 |
| --- | --- | --- |
| **LCP**（最大内容绘制） | 最大图片/文本块的渲染时间 | < 2.5s |
| **FCP**（首次内容绘制） | 第一个内容元素出现时间 | < 1.8s |
| **CLS**（布局偏移） | 图片加载导致的位置偏移 | < 0.1 |
| **TTI**（可交互时间） | 图片解码不阻塞交互 | < 3.8s |

### LCP 优化专用技巧

1. **首屏图片不要懒加载** → 用 `fetchpriority="high"` + 不设 `loading="lazy"`
2. **用 `preload` 提前加载 LCP 元素** → `<link rel="preload" as="image" ... />`
3. **避免首屏图片过大** → 使用 CDN 裁剪到实际显示尺寸
4. **用 picture 提供最优格式** → AVIF > WebP > JPEG

```html
<!-- LCP 优化示例：首页 Hero 图 -->

      imagesrcset="/hero-640.webp 640w, /hero-1080.webp 1080w, /hero-1920.webp 1920w"
      imagesizes="100vw" />

<img src="/hero-optimized.webp"
     srcset="/hero-640.webp 640w, /hero-1080.webp 1080w, /hero-1920.webp 1920w"
     sizes="100vw"
     fetchpriority="high"
     decoding="sync"
     width="1920"
     height="1080"
     alt="首页横幅" />
```

## 九、最佳实践清单

### 加载策略

- 首屏关键图片：`fetchpriority="high"` + `preload` + 不懒加载
- 视口外图片：`loading="lazy"` 或 Intersection Observer
- 用户交互附近图片：`rootMargin` 提前触发加载

### 格式与压缩

- 格式：AVIF > WebP > JPEG/PNG，用 `<picture>` 实现优雅降级
- 压缩：构建时自动压缩，目标文件大小 < 200KB（常规图）/ < 500KB（大图）
- 响应式：不同视口提供不同尺寸，手机不加载桌面图

### 缓存与 CDN

- 文件名带 content hash → `Cache-Control: immutable`
- 源站存原始图，CDN 按参数实时裁剪/转格式
- 不同 CDN 域名做冗余

### 用户体验

- 占位图 → 渐进加载 → 原图（三阶段平滑过渡）
- 用 `aspect-ratio` 或 `width/height` 属性预占空间，防止 CLS
- 加载失败 → 多级降级（压缩版 → 低质量版 → 占位图）

### 框架选择

- Next.js → 内置 `<Image />` 组件，零配置优化
- Nuxt → `<NuxtImg />` / `<NuxtPicture />` 组件
- Vite → `vite-imagetools` 构建时处理
- 无框架 → `srcset` + `<picture>` + `loading="lazy"`

---

> **一句话总结**：**格式选 AVIF，加载用懒加载 + 首屏预加载，尺寸靠响应式 + CDN，体验靠渐进式 + 容错降级，缓存用 immutable + CDN 冗余。**
