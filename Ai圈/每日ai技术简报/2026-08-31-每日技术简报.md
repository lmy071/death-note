## 1. Salesforce × Anthropic 推出 Claudeforce：Claude 直接进入企业 CRM 与工作流

Salesforce 与 Anthropic 公布 Claudeforce。首个产品是 **Salesforce in Claude**：一个带有 37 个预置销售 Skills 的 Claude Plugin，可直接基于 Salesforce 中的实时收入、客户与 Pipeline 上下文进行分析，并在 Salesforce 的业务规则与权限治理下执行更新。Claude 同时成为 Slack、Agentforce Vibes、Agentforce Coworker 等多处体验的重要默认模型。

**为什么值得关注：** 这是“企业软件 UI → Agent Interface”转型的典型案例。核心不再只是把聊天框嵌入 CRM，而是通过 **MCP、API、CLI + 权限治理**把业务数据和动作暴露给 Agent。对于企业内部前端/低代码平台，这意味着未来需要同时设计 Human UI 与 Agent 可调用能力层。

**原始来源：** [Salesforce 官方公告 — Salesforce and Anthropic Announce Claudeforce](https://www.salesforce.com/news/press-releases/2026/08/26/salesforce-and-anthropic-announce-claudeforce/)

## 2. Vercel Eve 进入 Dashboard：几步直接生成 Agent、私有 Git 仓库与部署项目

Vercel 8 月 28 日更新 Eve：现在可以直接从 Dashboard 的 **Add New → Agent** 创建 Agent。Builder 会生成 Eve 项目、创建私有 Git Repository，并部署成新的 Vercel Project；同时可选择 AI Gateway 中的模型、Next.js Web Chat 或 Slack Channel，并接入 Linear、Notion 或自定义 MCP Server。

**为什么值得关注：** Agent 开发正在越来越像现代前端应用开发：`Scaffold → Git → Deploy → Observe` 被压缩成一个平台工作流。Eve 本身又是 filesystem-first 的 TypeScript Agent Framework，这对熟悉 Vue / TypeScript 的前端团队很有参考价值——Agent 的 instructions、skills、tools 可以像普通代码资产一样进入仓库、Review 和 CI/CD。

**原始来源：** [Vercel Changelog — Build and deploy eve agents from the Vercel dashboard](https://vercel.com/changelog/build-and-deploy-eve-agents-from-the-vercel-dashboard)

## 3. Claude Code v2.1.248 加入 Restricted Mode：为 CI 与不可信仓库提供硬隔离开关

Claude Code v2.1.248 新增 `--restricted` / `CLAUDE_CODE_RESTRICTED=1`。开启后会移除内置命令/代码执行工具和默认 WebFetch，把文件工具限制在当前工作目录，拒绝 `bypassPermissions`，并忽略 user / project / local settings。该版本还加入 per-agent `experimental.cacheTtl`、自托管 Runner label 和更完整的 managed settings 诊断。

**为什么值得关注：** Coding Agent 真正进入 CI、客户仓库和自动化 Worker 后，Prompt 约束并不足够，需要**运行时硬边界**。Restricted Mode 给了团队一个更容易审计的最小权限起点：需要什么工具再显式开放什么，而不是默认把 Shell、网络和项目级设置都交给 Agent。

**原始来源：** [Anthropic Claude Code v2.1.248 官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.248)

## 4. Neon 把数据库直接装进 Coding Agent：新增 CLI 一键 MCP 配置与查询卡死检查

Neon 8 月 28 日 Changelog 新增三条面向 Coding Agent 的 CLI 路径，用来把 Neon 直接配置进 Cursor、Claude Code 等 Agent，而不再需要手动编辑 MCP 配置。同时 Neon MCP 增加 stalled-query 检查，帮助 Agent 识别长期阻塞或异常查询；官方还补充了新的 Agent/Backend 指南。

**为什么值得关注：** 数据库正在从“Agent 调 API 的外部服务”变成 Agent 原生开发环境的一部分。对全栈 TypeScript 项目而言，未来常见链路会变成：`Coding Agent → MCP → Database branch → migration / query / diagnose → Preview`。这会明显提高自动化开发效率，但也更需要 branch isolation、只读权限与查询审计。

**原始来源：** [Neon 官方 Changelog — 2026-08-28](https://neon.com/blog/category/changelog)

## 5. AWS AgentCore Evaluations：用 OpenTelemetry 统一评测不同 Agent Framework

AWS 发布 AgentCore Evaluations 的跨框架方案：只要 Agent 输出符合 OpenTelemetry / OpenInference 约定的 trace，就可以对 LangGraph、LlamaIndex、OpenAI Agents SDK、Google ADK、Claude Agent SDK、Strands Agents 等不同技术栈使用同一套评测。支持 Goal Success Rate、Correctness、Helpfulness、自定义 LLM-as-a-Judge，并可做 CI 中的按需评测或线上持续评测。

**为什么值得关注：** Agent 平台真正需要的不是“某个框架自己的 eval”，而是一层独立于 Harness 的 **Evaluation Plane**。如果团队未来同时使用 Codex、Claude、LangGraph 或自研 Agent，这种基于 OTel Trace 的统一评测方式更适合作为长期基础设施，并且能把任务完成率、工具调用轨迹和线上质量纳入 CI/CD。

**原始来源：** [AWS 官方 — Evaluate any agent framework with Amazon Bedrock AgentCore Evaluations](https://aws.amazon.com/blogs/machine-learning/evaluate-any-agent-framework-with-amazon-bedrock-agentcore-evaluations/)

## 今日结论

今天 5 条放在一起，主线非常清晰：

`Enterprise Data / Workflow → Agent Harness → Permissions → MCP / Tools → Deployment → OpenTelemetry → Evals`

过去 Coding Agent 的核心问题是“能不能把代码写出来”；现在更关键的问题正在变成：**能否以最小权限运行、能否接入真实业务系统、能否持续部署、以及能否用统一指标证明它真的完成了任务。**

对 Vue / TypeScript 团队来说，最值得提前建设的是三类资产：可机器读取的项目规范与 Skills、严格隔离的工具/数据权限，以及能进入 CI 的 Agent Evals。
