## 1. AWS 给长期 Agent 加“记忆垃圾回收”：自动评分、合并和清理旧记忆

AWS 9 月 4 日发布 AgentCore Memory 生命周期实践，针对长期运行 Agent 会不断积累过时上下文的问题，提出一套可部署的 nightly workflow：通过 TTL、相关性衰减评分和 LLM consolidation，对记忆进行过期、合并与清理。方案使用 AWS Step Functions、CloudTrail、S3、Lambda 与 AgentCore Evaluations，并提供 AWS CDK 实现。

**为什么值得关注：** Agent Memory 不能只解决“如何记住”，还必须解决“什么时候忘记”。旧 runbook、已解决工单或过时用户状态会直接污染后续决策。对长期 Coding Agent / 运维 Agent 来说，Memory Lifecycle 很可能会像数据库 retention policy 一样成为基础能力。

**原始来源：** [AWS — Designing lifecycle policies for AgentCore memory](https://aws.amazon.com/blogs/machine-learning/designing-lifecycle-policies-for-agentcore-memory/)

## 2. HyperPod InstantStart：AI Agent 开始直接管理 GPU 集群基础设施

AWS 9 月 4 日介绍开源 HyperPod InstantStart 控制平面：同一个后端同时提供 Web UI、REST API 和 MCP Tools，Kiro CLI Agent 可以通过自然语言创建 HyperPod 集群、配置容量、训练、推理和存储。关键点是 Agent 并不是直接自由调用 AWS CLI，而是通过带验证、持久状态和幂等重试的控制平面执行操作。

**为什么值得关注：** 这是非常典型的 Agent-ready Infrastructure 设计。正确模式不是 `LLM → Shell`，而是 `Agent → Skills / MCP → Guarded Control Plane → Cloud API`。这种架构同样适用于企业内部发布平台、低代码平台、CI/CD 和前端基础设施自动化。

**原始来源：** [AWS — Run agent-driven Amazon SageMaker HyperPod operations with InstantStart](https://aws.amazon.com/blogs/machine-learning/run-agent-driven-amazon-sagemaker-hyperpod-operations-with-instantstart/)

## 3. Intuit EWOK Agent：生产故障切换也开始交给 Agent，但执行仍保持确定性

Intuit 公布已实际运行约 8 个月的 EWOK Agent。工程师可以在内部 Portal 或 IDE 中直接输入类似“failover payments-gateway in production”的请求；模型负责理解意图、选择 typed skill 和处理异常分支，而真正的生产变更由传统、经过测试的 EWOK API 确定性执行，并保留审批、Guardrails、IAM 最小权限和审计记录。

**为什么值得关注：** 这给生产 Agent 划出了一条非常重要的边界：**模型决定做什么，传统代码决定怎么做。** 对会修改代码、部署服务、操作数据库的 Coding Agent 来说，这比让模型直接持有凭据并自由执行命令安全得多。

**原始来源：** [AWS / Intuit — How Intuit built an agentic disaster recovery assistant with Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/how-intuit-built-an-agentic-disaster-recovery-assistant-with-amazon-bedrock/)

## 4. AWS AI-DLC：Kiro + Claude Code + AgentCore 被组合成正式软件开发生命周期

AWS 9 月 3 日发布 AI-Driven Development Lifecycle 的两个参考实现，其中包含 SQL → ER Diagram Agent 和 Multi-Agent Code Security Analyzer，组合使用 Amazon Bedrock AgentCore、Kiro 与 Claude Code。官方建议将 Agent 拆成单一职责、使用持久 Memory、从第一天接入 OpenTelemetry，并对大输入采用 chunked processing。

**为什么值得关注：** Coding Agent 正从单一 IDE 工具变成 SDLC 中的可组合 Worker。对大型 Vue / TypeScript 项目，更值得建设的是可复用的 Agent 职责、项目 Skills、Trace 和持续评测，而不是不断堆叠 Prompt。

**原始来源：** [AWS — AI-driven development lifecycle using Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/ai-driven-development-lifecycle-using-amazon-bedrock-agentcore/)

## 5. Gemini Agentic Video：模型不再把整段视频一次性塞进上下文

Google 为 Gemini 3.7 Flash、3.6 Flash 和 3.5 Flash-Lite 推出 agentic video understanding。模型可以在分析过程中主动决定查看哪些时间段，而不是预先把全部视频帧加入上下文。Google 报告最高可降低 88% Token 消耗、66% 成本，并将质量最高提升约 7%。

**为什么值得关注：** 这代表多模态模型开始采用与 Coding Agent 类似的策略：先规划，再按需获取上下文。未来浏览器 Agent、UI 测试 Agent、游戏视频分析和前端视觉 QA，都可能从 `全量输入` 转向 `Agentic Context Retrieval`。

**原始来源：** [Google DeepMind — Introducing agentic video understanding with Gemini](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-agentic-video-in-gemini/)

## 今日结论

如果只看两条，优先关注 **AgentCore Memory Lifecycle** 和 **Intuit EWOK Agent**。

它们分别回答了生产 Agent 最关键的两个问题：

- **长期运行后，如何避免旧记忆污染决策？** → TTL + relevance scoring + consolidation + regression evals
- **Agent 可以操作生产系统时，如何避免模型直接掌握危险执行权？** → typed skills + deterministic executor + policy gates + audit

今天的 Agent 工程栈可以概括为：

`Model → Agent Harness → Memory Lifecycle → Skills / MCP → Guarded Control Plane → Deterministic Execution → Observability / Evals / Audit`

对于 Vue / TypeScript 团队，最值得借鉴的是：把 Agent 能力做成**明确 schema 的 Tool / Skill**，把真正产生副作用的操作放到传统、可测试、可审计的代码层，而不是让模型自由拼 Shell 或 API 调用。
