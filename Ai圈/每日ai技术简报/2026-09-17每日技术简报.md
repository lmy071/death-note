# 2026-09-17每日技术简报

## 今日技术主线

过去 24–48 小时最值得跟进的变化集中在 **Coding Agent 的可移植运行环境、企业自动化的 Agent 化、Agent 状态恢复、实时多模态模型，以及 AI 使用成本治理**。本期避开了前几日已报道且没有实质更新的内容。

## 1. VS Code 1.138：Agent Session 正式进入 Dev Container，并支持 Codex 跨应用续接

9 月 16 日发布的 VS Code 1.138 允许 Agent Session 直接运行在项目的本地 Dev Container 中，使用项目真实的工具链和依赖，而不是宿主机环境。新版还扩展 Codex Harness：同一个 Codex Session 可以在 ChatGPT App 与 VS Code 间继续，支持 Copilot / ChatGPT 订阅切换，并可使用 VS Code 内置、扩展和 MCP 工具。Automations 也已默认启用并支持导入/导出。

**为什么值得关注：** Coding Agent 的执行环境正在从“编辑器插件”升级成可隔离、可迁移的 Runtime。对 Vue / TypeScript 项目尤其直接：Node、pnpm、浏览器测试、构建依赖都可以固定在 Dev Container 中，降低 Agent 与开发者环境不一致导致的失败。

**原始来源：** [Visual Studio Code 1.138 Release Notes](https://code.visualstudio.com/updates/v1_138)

## 2. UiPath for Coding Agents 多项能力 GA：Claude Code / Codex / Cursor 可直接构建企业 Agent 与编排

UiPath 9 月 16 日把多项 Coding Agents 能力推进至 GA。Coding Agent 现在可以完整构建 UiPath Agent，包括 Python（LangGraph、LlamaIndex、OpenAI Agents）和低代码 Agent，并覆盖 Prompt、输入输出 Schema、Tool、Eval、打包和部署。与此同时，Maestro Flow、Coded Apps、API Workflow、Human-in-the-loop Task 与 IXP 项目也可以通过 Coding Agent 创建和发布。

**为什么值得关注：** Coding Agent 的作用域正在从“改代码”扩展为 `Agent → Workflow → UI → API Integration → Human Approval → Deployment`。这是一种非常明确的趋势：未来企业自动化平台会把 Coding Agent 当成统一的自然语言开发前端，而不是单独的辅助工具。

**原始来源：** [UiPath for Coding Agents — September 2026 Release Notes](https://docs.uipath.com/coding-agents/standalone/latest/release-notes/september-2026)

## 3. Cohesity Agent Resilience：开始备份和恢复 Agent 的 Memory、Config 与依赖关系

Cohesity 9 月 16 日发布 Agent Resilience，首批支持 Amazon Bedrock。它不仅保护 Agent 操作的数据，还会发现 Agent 与配置、Memory Store、数据资源之间的依赖，并允许在 Memory 被污染或配置漂移后恢复到可信状态。官方的 Agent Topology 还用于评估一个 Agent 故障后的完整 Blast Radius。

**为什么值得关注：** Agent 的 Disaster Recovery 开始成为独立基础设施问题。生产 Agent 需要恢复的不再只有数据库和文件，而是 `Agent State + Memory + Configuration + Credentials + Dependencies`。这会成为长期运行 Agent 和企业 Agent 平台必须补齐的一层。

**原始来源：** [Cohesity — Agent Resilience](https://www.cohesity.com/newsroom/press/cohesity-introduces-agent-resilience-to-protect-ai-agent-infrastructure/)

## 4. Gemini 3.8 Live / Extended Thinking 进入 Vercel AI Gateway：语音与推理可以并行运行

Vercel 已在 AI Gateway 上提供 Google Gemini 3.8 Live 与 Gemini 3.8 Live Extended Thinking。普通 Live 版本支持实时音频、视觉 Grounding、97 种语言自动切换以及对话不中断的后台 Tool Call；Extended Thinking 版本则可以在持续语音交互的同时并行执行多步推理。开发者可直接通过 AI SDK Realtime API 和 WebSocket 使用。

**为什么值得关注：** 实时 Agent 架构正在从 `Listen → Think → Tool → Speak` 的串行流水线变成 `Conversation || Reasoning || Tool Execution`。对于浏览器助手、游戏 NPC、客服和实时操作型 Agent，这会显著改善等待感和交互连续性。

**原始来源：** [Vercel — Gemini 3.8 Live models on AI Gateway](https://vercel.com/changelog/gemini-3-8-live-models-now-available-on-ai-gateway)

## 5. GitHub Copilot Budget Increase Requests GA：Agent / AI Credit 开始进入企业实时成本治理

GitHub 9 月 16 日宣布 Copilot Budget Increase Requests GA。成员耗尽 Copilot AI Credits 后，可以直接请求增加额度；请求会自动路由到实际承担预算的 Organization 或 Enterprise，管理员可以批准、调整或拒绝，批准后立即恢复 AI Credit 使用权限。该功能面向 Copilot Business / Enterprise 的 usage-based billing。

**为什么值得关注：** 随着 Coding Agent、Code Review、模型路由和后台任务持续消耗推理资源，AI 成本治理会从月末账单分析变成 Runtime Control。企业研发平台需要逐渐管理 `User / Agent → Budget → Model → Task → Cost → Outcome`，否则 Agent 并发规模越大，成本越难控制。

**原始来源：** [GitHub Changelog — Copilot budget increase requests are generally available](https://github.blog/changelog/2026-09-16-copilot-budget-increase-requests-are-generally-available/)
