## 1. DeepSeek V4 Flash Vision Exp 开放权重：305B 多模态 Agent 模型可本地研究

![DeepSeek V4 Flash Vision](https://www.pcgameshardware.de/screenshots/original/2026/08/DeepSeek-V4-Flash-Vision-pcgh_artwork.jpeg)

DeepSeek V4 Flash Vision

DeepSeek 的 `DeepSeek-V4-Flash-Vision-Exp` 官方 Hugging Face 仓库现已提供模型权重、Tokenizer、Prompt Encoder 与最小推理代码，许可证为 MIT。模型规模约 305B 参数，是 V4 系列首个实验性多模态模型；官方模型卡称其在保持文本 Agent 能力的同时，重点提升视觉理解和多模态 Agent 表现。

**为什么值得关注：** 这使此前主要通过 API 体验的视觉 Agent 能力进入可下载、可审计、可二次研究阶段。对需要处理截图、UI、图表、网页视觉信息的 Coding Agent / Browser Agent，本地部署与私有化评估空间明显扩大。

**原始来源：** [DeepSeek 官方 Hugging Face 模型页](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-Vision-Exp) · [DeepSeek Vision API 文档](https://api-docs.deepseek.com/guides/vision/)

## 2. AWS Agent Registry 正式 GA：Agent、MCP、Skills 开始有统一企业级目录

![Amazon Bedrock AgentCore](https://docs.aws.amazon.com/images/bedrock-agentcore/latest/devguide/images/agentcore_all_components_final.png)

Amazon Bedrock AgentCore

AWS 8 月 31 日宣布 Agent Registry 正式 GA。它为 Agent、MCP Server、Skills 和自定义资源提供统一的可搜索目录，并加入所有者、生命周期、审批、访问控制、审计与语义/关键词混合搜索。Registry 自身还可作为 MCP Server 暴露给 Kiro、Claude Code 等 MCP 客户端。

**为什么值得关注：** Agent 数量从个位数增长到数百个之后，真正的问题会从“怎么做一个 Agent”变成“有哪些 Agent、谁维护、是否通过安全审核、哪个该被调用”。Registry 正在承担类似企业软件里的 Service Registry + Package Catalog + Governance Plane。

**原始来源：** [AWS 官方：Manage agents, tools and skills at scale with AWS Agent Registry](https://aws.amazon.com/blogs/machine-learning/manage-agents-tools-and-skills-at-scale-with-aws-agent-registry/)

## 3. GitHub Agentic Workflows 加入 cooldown / stop-after：给持续 Agent 自动化加刹车

![GitHub Agentic Workflows](https://www.lemon-web.net/images/blog_articles/2326/GitHubBringsAgenticWorkflows.jpg)

GitHub Agentic Workflows

GitHub Agentic Workflows 在 8 月 31 日周更中连续发布 `v0.87.5`、`v0.87.8`、`v0.87.9` 预发布版。新版本加入 `on.cooldown`，可避免高频 Trigger 不断堆积；`on.stop-after` 现在支持 GitHub Actions 表达式，还改进了 Codex Harness 工具 Schema 的错误诊断。

**为什么值得关注：** Repo Agent 真正长期开启后，必须处理触发风暴、无限运行、成本失控和工具错误。`cooldown + stop-after` 这种看似普通的控制能力，实际上是 Agent 从 Demo 走向 CI/CD 生产自动化的重要标志。

**原始来源：** [GitHub Agentic Workflows：Weekly Update – August 31, 2026](https://github.github.com/gh-aw/blog/2026-08-31-weekly-update/) · [GitHub Next：Agentic Workflows](https://githubnext.com/projects/agentic-workflows/)

## 4. OpenClaw 2.0 发布：开源 Agent Runtime 继续向持久化基础设施演进

![OpenClaw](https://cdn.goclaw.sh/blog/1775482304007-what-is-openclaw-2.jpg)

OpenClaw

OpenClaw 发布 `v2026.8.1`，官方称为 **OpenClaw 2.0**。这一版本集中更新了 Release / CI、Plugin SDK 兼容性和原生应用分发等基础能力，并延续 OpenClaw 在多模型、插件、Gateway 和长期 Agent 运行环境上的工程化方向。

**为什么值得关注：** 开源 Agent 平台的竞争重点正在从“能调用几个模型和工具”转向升级兼容、Plugin 生命周期、Session / Gateway 稳定性以及跨环境运行。对希望自托管 Agent Runtime 的团队，这类基础设施成熟度比 Demo 能力更关键。

**原始来源：** [OpenClaw 官方 Release Notes：v2026.8.1 / OpenClaw 2.0](https://docs.openclaw.ai/releases/2026.8.1)

## 5. Codex 正式淘汰 GPT-5.4 系列登录态模型：默认迁移到 GPT-5.6 Terra / Luna

![OpenAI Codex](https://cdn.prod.website-files.com/62233c592d2a1e009d42f46c/6974e6b53d3f5bf43e40df13_6932e0dd2a73f326a9ac6239_Codex-agent-coding-chatgpt-openai.webp)

OpenAI Codex

OpenAI 的 Codex 支持说明确认：自 8 月 31 日起，通过 ChatGPT 账户登录 Codex 时，`GPT-5.4` 与 `GPT-5.4 mini` 不再可用；官方分别建议迁移到 `GPT-5.6 Terra` 与 `GPT-5.6 Luna`。这一变化不影响 OpenAI API，也不影响使用自有 API Key 的 Codex。

**为什么值得关注：** Coding Agent 已经进入快速模型生命周期阶段。团队如果在 Workspace 默认值、保存的模型配置或自动化中写死模型 ID，就需要把 **Model Lifecycle / Fallback / Routing** 当成正式工程能力，而不是一次性配置。

**原始来源：** [OpenAI Help：Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540)

## 今日结论

如果只看两条，优先关注 **AWS Agent Registry** 与 **GitHub Agentic Workflows 的 cooldown / stop-after**。

它们共同说明 Agent 工程栈正在快速补齐传统分布式系统早已存在的能力：

`Models → Agent Harness → MCP / Skills → Registry → Trigger → Runtime → Rate / Time Limits → Observability → Governance`

对于 Vue / TypeScript 团队，今天虽然没有值得单独占据 Top 5 的 Vue 或 TypeScript 新版本，但 Agent 对前端工程的影响继续加深：组件能力、内部工具、CI 工作流和项目规范越来越需要以机器可发现、可调用、可审计的形式暴露。
