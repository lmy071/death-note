# 2026-09-11每日技术简报

## 每日技术简报 · 2026-09-11

今天的主线是：**Agent 正从即时聊天进一步转向可调度、可持久化、可评测的后台工作流；与此同时，开发者工具正在把 Agent 直接纳入 IDE 与数据分析环境。**

### 1. VS Code 1.137：Agent Automations 进入 Preview，IDE 开始原生调度长期任务

![VS Code Agents](https://code.visualstudio.com/assets/agents/hero-agents-window-dark.png)

VS Code Agents

**摘要：** Visual Studio Code 1.137 于 9 月 9 日发布，新增 Agent Automations Preview，可按小时、每天或每周调度 Agent 任务，也可以手动触发。新版还加入实验性的 Voice Mode、GitHub Issue/PR 直接上下文接入，以及 Agent-queued messages，让忙碌 Session 可以排队处理跨 Session 消息。

**为什么值得关注：** Coding Agent 正从“开发者主动打开 Chat 使用”升级为 IDE 内部的后台 Worker。对 Vue / TypeScript 项目，这意味着 Issue triage、依赖检查、Bug 搜索、PR 准备等工作可以逐渐变成持续执行的自动化任务，而不是一次性 Prompt。

**原始来源：** [Visual Studio Code 1.137 Release Notes](https://code.visualstudio.com/updates/v1_137)

### 2. AWS 开源 Pizza Bot：为后台 Agent 设计“收件箱式”异步协作界面

**摘要：** AWS 9 月 10 日开源 Pizza Bot，它把长时间 Agent 工作组织成类似邮件的 Thread：任务可手动启动、定时启动或由 Webhook 触发，完成结果进入 Unread，需要人工批准的步骤进入 Action。它支持 MCP、Agent Skills、多模型提供商和 Ollama 本地模型，并通过 LangGraph / DeepAgents 将 Thread、Checkpoint、Memory 和审批状态持久化到本地 SQLite 与文件系统。

**为什么值得关注：** 这是对 Agent 产品交互模型的一次重要变化：长任务不应该要求用户一直盯着聊天窗口。更合理的架构正在变成 `Task → Background Run → Durable State → Approval Queue → Notification / Inbox`。这对于研发 Agent、运营 Agent 和个人助理都很有参考价值。

**原始来源：** [AWS Open Source Blog — Introducing Pizza Bot](https://aws.amazon.com/blogs/opensource/introducing-pizza-bot-an-open-source-inbox-for-ai-agents-that-work-in-the-background/)

**摘要：** Google 9 月 9 日发布 ADK for Kotlin 1.0，达到与 ADK 1.0 Core 的功能对齐，并针对 Android 提供 on-device 扩展。开发者可以通过 LiteRT-LM / ML Kit 运行本地 Agent，也能通过 Firebase AI Logic 编排云端模型；Room 与 AppSearch 可用于在进程重启后持久化 Agent 状态。

**为什么值得关注：** Agent Runtime 正从服务端 Python / TypeScript 进一步扩展到移动端。`On-device Model + Local State + Cloud Model + Tool Orchestration` 的混合模式，对低延迟、隐私敏感和离线场景尤其重要，也说明 Agent SDK 正从实验框架转向跨平台应用基础设施。

**原始来源：** [Google Developers Blog — ADK for Kotlin 1.0](https://developers.googleblog.com/announcing-adk-for-kotlin-10-building-production-ready-ai-agents-in-kotlin-android-and-beyond/)

### 4. AWS 提出 AEM：多轮 Agent 评测开始从最终得分追踪到“哪一轮先出错”

**摘要：** AWS 9 月 10 日发布 Agent Evaluation Metric（AEM）方法，用可分解、逐轮的指标评估多轮 Agent。其核心动机是：某次错误 Tool Call 可能污染后续所有步骤，而只看最终任务成功与否无法判断真正的故障起点。首篇文章重点展示 correctness 维度如何区分“根因错误”与“继承错误”。

**为什么值得关注：** 长周期 Agent 的 Eval 不能继续沿用单轮聊天评分思路。未来更实用的评测栈需要记录 `Turn → Tool Call → State Change → Downstream Effect`，否则很难定位模型、工具、Prompt 或状态管理哪一层导致失败。

**原始来源：** [AWS — Agent Evaluation Metric for multi-turn conversations](https://aws.amazon.com/blogs/machine-learning/agent-evaluation-metric-for-multi-turn-conversations/)

### 5. OpenAI 在 ChatGPT Work 与 Codex 加入 Data Plugin：Agent 直接进入企业数据分析工作流

**摘要：** OpenAI 9 月 10 日更新 Release Notes，Data Plugin 已可用于 ChatGPT Work 与 Codex。用户可以连接企业数据后提出业务问题、调查指标变化，并生成交互式 Dashboard 或 Report；分析过程可以结合团队自己的指标定义和业务上下文，并继续沿用连接账户的权限控制。

**为什么值得关注：** Coding / Work Agent 的边界正在从代码和文件进一步扩展到业务数据。对工程团队而言，未来 Agent 可以在同一工作流中完成 `读取指标 → 定位异常 → 检查代码 / 部署 → 形成报告`，这会推动研发与数据分析工具链进一步融合。

**原始来源：** [OpenAI — ChatGPT Release Notes（2026-09-10 Data plugin）](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 今日优先阅读

如果只看两条，建议优先关注 **VS Code 1.137 Agent Automations** 和 **Pizza Bot**。它们共同指向一个明显变化：Agent 的核心交互单位正在从实时 Chat Session 转向**长期存在、异步执行、可恢复、可审批的任务线程**。

当前值得持续关注的 Agent 工程栈可以概括为：

`Trigger / Schedule → Agent Session → Durable State → Tools / MCP → Approval → Eval → Inbox / Notification`

Vue / TypeScript 在过去 24–72 小时没有出现与上述内容同等级别的官方重大版本，因此今天没有重复较旧版本新闻来补足名额。
