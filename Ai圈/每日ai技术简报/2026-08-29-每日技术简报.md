## 1. 腾讯开源 Hy4 preview：770B MoE、49B 激活、上下文突破 100 万 Token

腾讯于 8 月 28 日正式发布并开源 Hy4 preview。该模型总参数 770B、每 Token 激活 49B，支持超过 1M Token 的上下文窗口，并重点面向代码、办公、科学研究等真实生产力任务。官方同时将其接入 WorkBuddy、CodeBuddy、腾讯云 TokenHub 和 OpenRouter。

**为什么值得关注：** 对 Coding Agent 来说，1M 上下文意味着更有机会把大型仓库、需求文档、日志和工具输出放进同一个长任务上下文中。更关键的是，这是一款可下载权重的超大 MoE 模型，使企业和研究团队可以在自有基础设施上评估旗舰级 Agent 模型，而不必完全依赖闭源 API。

**原始来源：** [Tencent 官方公告 — Tencent Releases and Open-Sources Tencent Hy4 preview](https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/) · [Hy4 preview 官方 GitHub](https://github.com/Tencent-Hunyuan/Hy4-preview)

## 2. [Z.ai](http://Z.ai) 开放 GLM-5.3 权重：复杂 Coding 与长任务成为核心方向

[Z.ai](http://Z.ai) 在 8 月 28–29 日开放 GLM-5.3 权重。官方模型卡表示，GLM-5.3 与 5.2 使用相同基础模型，本轮提升主要来自 post-training；[Z.ai](http://Z.ai) 宣称其内部 Code Bench 相比 GLM-5.2 提升约 50%，并在 Terminal Bench 3.0、Agents' Last Exam 等 Agent/Coding 测试上取得显著提升。

**为什么值得关注：** 这说明当前模型竞争的增量越来越多来自 Agent-oriented post-training，而不是单纯扩大基础模型。对开发团队而言，值得关注的不只是一次性代码生成能力，而是模型能否在数十乃至数百轮工具调用、测试和修复循环中持续有效工作。厂商 Benchmark 仍应结合自己的 Vue / TypeScript 仓库做独立评测。

**原始来源：** [Z.ai 官方 Hugging Face — GLM-5.3](https://huggingface.co/zai-org/GLM-5.3) · [GLM-5.3 README / Benchmark](https://huggingface.co/zai-org/GLM-5.3/blob/main/README.md)

## 3. Claude Code 2.1.251：模型切换 Hook、支出上限与 Agent 安全边界同步增强

Anthropic 于 8 月 28 日发布 Claude Code 2.1.251。新版本加入 `PreModelSwitch` / `PostModelSwitch` Hook，可在模型切换前后执行策略；Remote Control 可以实时查看前台 Sub-agent 的工具调用；`/usage` 增加 Spend Limit，`/cost` 增加 Prompt Cache 命中、重缓存 Token 等诊断。同时版本还集中修复了 symlink、plugin path、shell approval、managed settings 等一批权限和信任边界问题。

**为什么值得关注：** Coding Agent 正从“会写代码的 CLI”变成可治理的工程 Runtime。模型路由、成本、缓存、子 Agent 可观测性和权限边界开始进入同一套产品控制面。团队部署 Claude Code 时，可以开始把 Hook 当作 Policy Layer，例如限制高成本模型切换、对敏感仓库执行额外审批。

**原始来源：** [Anthropic Claude Code 官方 CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) · [npm — @anthropic-ai/claude-code 2.1.251](https://www.npmjs.com/package/@anthropic-ai/claude-code)

## 4. OpenAI 被曝测试 Codex Persistent Mode：Coding Agent 向“持续工作”迈进

Wired 8 月 28 日报道称，OpenAI 正在测试 Codex 的 Persistent mode。与当前任务完成后自动停止不同，该模式目标是让 Agent 持续工作直到用户手动终止，并包含一定程度的主动生成后续任务和通知能力。目前该功能仍处于测试阶段，OpenAI 尚未正式发布，因此功能细节和最终形态都可能变化。

**为什么值得关注：** 如果长期运行 Agent 成为正式产品能力，软件开发流程会从“人发起一次任务”继续转向“Agent 持续维护目标”。这也会同步放大权限、错误累积、资源成本和 Prompt Injection 风险，因此持久 Agent 的核心竞争点不仅是自主性，还包括可停止性、审计、权限和异常恢复。

**原始来源：** [Wired — OpenAI Is Developing a 'Persistent' AI Agent](https://www.wired.com/story/openai-is-developing-a-persistent-ai-agent/)

## 5. A2UI v0.9.1 / v1.0 Candidate：Agent 开始用协议直接“生成 UI”

A2UI（Agent-to-User Interface）项目当前生产版本为 v0.9.1，v1.0 已进入 Candidate。它定义了一套基于流式 JSON 的声明式 UI 协议：Agent 不直接执行 HTML/JavaScript，而是发送 `createSurface`、`updateComponents`、`updateDataModel` 等消息，由 Web、移动端或桌面客户端用自己的可信组件库渲染。v1.0 Candidate 进一步加入 client-to-server RPC（`actionResponse`）等能力。

**为什么值得关注：** 这是今天对前端最有价值的一条。未来 Agent 不一定只返回 Markdown 文本，也可以根据任务动态生成表单、图表、地图、确认卡片等交互界面。对 Vue / TypeScript、低代码平台和设计系统来说，这意味着可能出现新的架构层：`Agent → UI Protocol → Component Catalog → Vue Renderer`。由于 Agent 只能引用预批准组件，也比直接让模型输出并执行任意前端代码更容易治理。

**原始来源：** [A2UI 官方网站](https://a2ui.org/) · [A2UI v1.0 Protocol Specification](https://github.com/a2ui-project/a2ui/blob/main/specification/v1_0/docs/a2ui_protocol.md) · [A2UI 官方 GitHub](https://github.com/a2ui-project/a2ui)

## 今日结论

如果今天只看两条，优先看 **腾讯 Hy4 preview** 和 **Claude Code 2.1.251**。

Hy4 preview 体现的是模型侧的变化：开源旗舰模型继续向超长上下文、Coding 和 Agent 任务靠拢；Claude Code 体现的是 Harness 侧的变化：真正进入生产后，Agent 必须同时解决模型路由、成本、缓存、权限和可观测性。

而 A2UI 则提示了前端下一阶段值得关注的方向：

`LLM / Planner → Agent Harness → Tools / MCP → A2UI → Vue / React / Native Component Catalog`

对前端工程来说，未来值得投入的不只是“让 AI 帮忙写 Vue”，还包括如何设计一套 **Agent 可安全调用、可动态组合、可被用户确认的 UI 组件系统**。
